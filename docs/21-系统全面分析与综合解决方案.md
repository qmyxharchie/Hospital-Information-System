## 第一部分：GitHub Issue #17 逐条分析与解决方案

### 问题一（对应 Issue #17 第七点）：UI 菜单输入安全 — scanf 无返回值校验

**问题描述**：所有 `scanf("%d", &choice)` 均未检查返回值；用户输入字母时变量未赋值，`choice` 保持随机值导致 `switch` 异常或死循环。

**影响范围**：`ui.c` 全部菜单函数（`showLoginPage`、`showMainMenuByRole`、`showPatientManagement`、`showDoctorManagement`、`showMedicineManagement`、`showHospitalizationManagement`、`showBedManagement`、`showRegistrationManagement`）

**解决方案**：统一封装输入函数 + 每个菜单注入校验

```c
// ui.c 顶部添加
#include <stdbool.h>

// 安全的整数输入函数（带清缓冲）
int safeReadInt(const char* prompt, int minVal, int maxVal) {
    int choice;
    char buf[100];
    while (true) {
        printf("%s", prompt);
        if (scanf("%d", &choice) != 1) {
            // 清除错误输入
            fgets(buf, sizeof(buf), stdin);
            printf("[ERROR] 输入无效，请输入数字！\n");
            continue;
        }
        getchar(); // 吃掉换行
        if (choice < minVal || choice > maxVal) {
            printf("[ERROR] 请输入 %d~%d 之间的数字\n", minVal, maxVal);
            continue;
        }
        return choice;
    }
}

// 安全读取 double
double safeReadDouble(const char* prompt) {
    double val;
    char buf[100];
    while (true) {
        printf("%s", prompt);
        if (scanf("%lf", &val) != 1) {
            fgets(buf, sizeof(buf), stdin);
            printf("[ERROR] 输入无效，请输入数字！\n");
            continue;
        }
        getchar();
        return val;
    }
}

// 安全读取字符串（带长度限制）
void safeReadString(const char* prompt, char* buf, int maxLen) {
    printf("%s", prompt);
    if (scanf("%99s", buf) == 1) {
        if ((int)strlen(buf) >= maxLen) {
            printf("[WARNING] 输入过长，已截断至 %d 字符\n", maxLen - 1);
            buf[maxLen - 1] = '\0';
        }
    }
    getchar();
}
```

**用法示例**（以 `showLoginPage` 为例）：

```c
// 改造前
scanf("%d", &choice);
getchar();

// 改造后
choice = safeReadInt("请选择: ", 0, 3);
```

### 问题二（对应 Issue #17 第二点）：rebuild 类函数被多次调用

**问题描述**：同一次业务流程中 `rebuildXxxFile()` 被重复调用，导致不必要的文件 I/O。

**典型案例**：
- `completeRegistration()` 内部已调用 `rebuildRegistrationFile()`，但 `ui.c` 的 case 8 又调用了一次
- `dischargePatient()` 和 `ui.c` 都分别调用 `rebuildHospitalizationFile()` + `rebuildBedFile()`
- `addRegistration()` 内部已调用 `rebuildRegistrationFile()`

**解决方案**：**UI 层不再主动调用 rebuild**，由业务函数负责统一管理。

| 位置 | 修改方式 |
|------|---------|
| `ui.c` case 8（完成就诊） | 删除 `rebuildRegistrationFile(g_regHead);` 这行 |
| `ui.c` case 2（出院结算） | 确认 `dischargePatient()` 内部已调用 rebuild 后，删除 UI 层的重复调用 |
| `ui.c` case 7（追加预交金） | 确认 `addPrepay()` 内部已调用 rebuild 后，删除 UI 层的重复调用 |

**原则**：每个业务函数（`addXxx`/`delXxx`/`modifyXxx`/`completeXxx`）自己保证数据持久化，UI 只负责调用业务函数。

### 问题五（对应 Issue #17 第八点）：全局指针管理

**问题描述**：全局链表头尾指针（`g_patientHead`/`g_patientTail` 等）暴露方式不统一，有的模块用 `extern`，有的用 Getter，存在多重定义风险。

**当前状态**：
- `patient.c`：提供 `getPatientHead()`/`getPatientTail()` Getter
- `doctor.c`：提供 `getDoctorHead()`/`getDoctorTail()` Getter
- `bed.c`/`hospitalization.c`：直接 `extern` 声明
- `ui.c`/`file_io.c`：通过 `extern` 使用

**解决方案**：统一采用 **"单一定义 + 头文件 extern 声明"** 模式

```c
// 1. 在 ui.h 中统一声明所有全局指针（已有）
extern Patient* g_patientHead;
extern Patient* g_patientTail;
extern Doctor* g_doctorHead;
extern Doctor* g_doctorTail;
// ... etc

// 2. 各模块 .c 文件中只定义一次，不在 .h 中定义
// patient.c
Patient* g_patientHead = NULL;
Patient* g_patientTail = NULL;

// doctor.c
Doctor* g_doctorHead = NULL;
Doctor* g_doctorTail = NULL;

// 3. 不再在模块 .c 文件中使用 static 修饰全局变量
// 4. 统一通过 ui.h 引用，不再各自 extern

// 5. Getter 函数保留但标记为 deprecated，逐步迁移到直接访问
```

**推荐做法**：在 `ui.h`（或其他集中头文件如 `globals.h`）中用 `extern` 声明，在某个 `.c` 文件中实际定义一次，所有使用者都通过头文件引用。

## 第四部分：CMake 使用方法与配置文件

### 为什么用 CMake

| VS2022 直接建项目 | Makefile | CMake |
|------------------|----------|-------|
| 需手动添加每个 .c 文件 | 仅支持 Linux/MinGW | **跨平台**（VS/CLion/Linux） |
| 无跨平台能力 | 语法晦涩 | 语法清晰 |
| 换电脑需重新配置 | Windows 需装 MinGW | VS2022 **内置支持** |

### CMakeLists.txt（项目根目录）

```cmake
# CMakeLists.txt — 医院信息管理系统
# 最低 CMake 版本要求
cmake_minimum_required(VERSION 3.10)

# 项目名称 + 版本
project(HospitalInformationSystem VERSION 1.0 LANGUAGES C)

# 设置 C 标准
set(CMAKE_C_STANDARD 99)
set(CMAKE_C_STANDARD_REQUIRED ON)

# ============ 源文件收集 ============
# 手动列出所有 .c 文件（推荐，控制精确）
set(SOURCES
    src/main.c
    src/ui.c
    src/login.c
    src/patient.c
    src/doctor.c
    src/registration.c
    src/medicine.c
    src/hospitalization.c
    src/bed.c
    src/file_io.c
    src/utils.c
)

# ============ 头文件路径 ============
include_directories(${CMAKE_SOURCE_DIR}/include)

# ============ 生成可执行文件 ============
add_executable(HospitalSys ${SOURCES})

# ============ 平台特定配置 ============
if(WIN32)
    # Windows 下可能需要关闭某些警告
    target_compile_options(HospitalSys PRIVATE /W3)
    
    # 如果需要 system("pause") 和 system("cls") 的支持（已存在）
    # Windows 控制台程序
    set_target_properties(HospitalSys PROPERTIES
        VS_DEBUGGER_WORKING_DIRECTORY "${CMAKE_SOURCE_DIR}"
    )
else()
    # Linux/macOS 编译选项
    target_compile_options(HospitalSys PRIVATE -Wall -Wextra -g)
endif()

# ============ VS2022 文件夹组织 ============
# 让 .c 文件在 Solution Explorer 中按目录分组
source_group(TREE ${CMAKE_SOURCE_DIR}/src PREFIX "Source Files" FILES ${SOURCES})

# ============ 数据文件复制（可选） ============
# 构建时自动将 data/ 文件夹复制到输出目录
add_custom_command(TARGET HospitalSys POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_directory
    ${CMAKE_SOURCE_DIR}/data $<TARGET_FILE_DIR:HospitalSys>/data
    COMMENT "复制数据文件到输出目录"
)
```

### 在 VS2022 中使用 CMake

**步骤 1：安装 CMake 工具**
```
VS2022 安装器 → 修改 → 单个组件 → 搜索 "CMake" → 勾选
"用于 Windows 的 C++ CMake 工具"
```

**步骤 2：打开项目**
```
文件 → 打开 → CMake → 选择项目根目录（含 CMakeLists.txt）
```
VS2022 会自动识别 CMakeLists.txt。

**步骤 3：构建运行**
```
菜单栏：CMake → 生成 → 生成全部 (Ctrl+Shift+B)
绿色箭头运行，或 CMake → "HospitalSys" → 设为启动项 → 运行
```

**步骤 4：添加新文件**
在 `src/` 或 `include/` 下新建文件后，CMake 会自动识别（因为手动列出了每个文件，需编辑 CMakeLists.txt 添加新 .c 文件）。

如需自动收集，可替换为：
```cmake
# 自动收集 src 目录下所有 .c 文件（懒人模式）
file(GLOB SOURCES "src/*.c")
# 注意：GLOB 不会自动检测新增文件，有时需重新生成 CMake
```
