# 医院信息管理系统 - 问题修复清单

> 本清单基于对 `qmyxharchie/Hospital-Information-System` 仓库（截至 2026-05-07）的代码审查整理。
> 按优先级分为 **P0（阻塞编译）**、**P1（核心功能缺失）**、**P2（运行时逻辑缺陷）**、**P3（完善性）** 四级。

---

## P0 — 语法/编译错误（不修无法通过编译）

### P0-1 `doctor.c`：`findDoctorsByName()` 括号不匹配

| 项目 | 内容 |
|------|------|
| **位置** | `src/doctor.c`，约第 193 行 |
| **问题** | `if ((strstr(d->data.name, name) != NULL)` 多一个左括号，缺少右括号 `)` |
| **影响** | 语法错误，直接编译失败 |
| **修复** | 改为 `if (strstr(d->data.name, name) != NULL)` |

### P0-2 `doctor.c`：`incrementPatientCount()` 缺少分号

| 项目 | 内容 |
|------|------|
| **位置** | `src/doctor.c`，约第 265 行 |
| **问题** | `printf("此医生已达每日最大接诊次数\n")` 末尾无 `;` |
| **影响** | 语法错误，直接编译失败 |
| **修复** | 末尾补 `;` |

### P0-3 `doctor.h`：`modifyDoctor()` 参数类型错误

| 项目 | 内容 |
|------|------|
| **位置** | `include/doctor.h`，函数声明 |
| **问题** | `int modifyDoctor(Doctor* head, char empNo, DoctorData newData);` |
| **影响** | `char empNo` 只能存一个字符，工号 "DOC001" 传入时截断，导致永远找不到目标 |
| **修复** | 改为 `char* empNo`；同步修改 `src/doctor.c` 中实现签名 |

### P0-4 `doctor.c`：`modifyDoctor()` 中 `dept` 拷贝长度错误

| 项目 | 内容 |
|------|------|
| **位置** | `src/doctor.c`，约第 157 行 |
| **问题** | `safeStringCopy(target->data.dept, newData.dept, 20)` |
| **影响** | `dept` 字段定义为 `char[50]`，长度 20 会在科室名较长时截断 |
| **修复** | 改为 `safeStringCopy(target->data.dept, newData.dept, 50)` |

### P0-5 `medicine.c`：`addPurchaseRecord()` 对数值字段使用 `strcpy`

| 项目 | 内容 |
|------|------|
| **位置** | `src/medicine.c`，约第 145~147 行 |
| **问题** | `strcpy(pur->data.quantity, quantity)` 和 `strcpy(pur->data.totalCost, totalCost)` |
| **影响** | `quantity` 是 `int`，`totalCost` 是 `double`，`strcpy` 会导致严重内存损坏和数据错误 |
| **修复** | 改为直接赋值：`pur->data.quantity = quantity;` 和 `pur->data.totalCost = totalCost;` |

### P0-6 `hospitalization.c`：`addHospitalization()` 对 `double` 使用 `strcpy`

| 项目 | 内容 |
|------|------|
| **位置** | `src/hospitalization.c`，约第 43 行 |
| **问题** | `strcpy(h->data.prepay, prepay)` |
| **影响** | `prepay` 是 `double`，`strcpy` 会把 8 字节的浮点数值误当字符串拷贝，导致数据损坏 |
| **修复** | 改为 `h->data.prepay = prepay;` |

### P0-7 `hospitalization.h`：重复/错误结构体定义

| 项目 | 内容 |
|------|------|
| **位置** | `include/hospitalization.h` |

| **修复** | 删除 `HospitalizationNode`，只保留 `Hospitalization` 一个结构体定义 |

### P0-8 `medicine.h`：重复结构体定义

| 项目 | 内容 |
|------|------|
| **位置** | `include/medicine.h` |

| **影响** | 如果 P0-7/P0-8 已修复，这些类型别名指向的结构体已不存在，编译报错 |
| **修复** | 统一改为 `Medicine*`、`Purchase*`、`Hospitalization*`、`Bed*` |

## P2 — 运行时逻辑缺陷（能编译但会出错或行为异常）

### P2-1 `bed.c`：`freeBed()` 命名误导

| 项目 | 内容 |
|------|------|
| **位置** | `src/bed.c` |
| **问题** | `freeBed()` **没有释放内存**，只是清空字段（`strcpy(patientCardNo, "无")` 等） |
| **影响** | 命名与 `freeXxxChain()` 系列混淆，开发者可能误以为已释放内存导致内存泄漏排查困难 |
| **修复** | 建议重命名为 `clearBed()` 或 `releaseBed()`；`freeBed()` 名称保留给真正释放节点内存的函数 |

### P2-2 `doctor.c`：`findDoctorsByName()` 返回结果链表未释放风险

| 项目 | 内容 |
|------|------|
| **位置** | `src/doctor.c` |
| **问题** | 返回新分配的 `resultHead` 结果链表，调用方需手动 `freeDoctorsResultChain()` |
| **影响** | 容易遗漏释放，造成内存泄漏；且该函数名是复数 `Doctors` 但返回值是单指针，语义略混 |
| **修复** | 在文档和 UI 教程中强调必须释放；或改为在函数内部打印结果而不返回新链表 |

### P2-3 `medicine.c`：`findMedicineByName()` 循环条件与指针解引用错误

| 项目 | 内容 |
|------|------|
| **位置** | `src/medicine.c`，约第 90~92 行 |
| **问题** | `while (cur->next != NULL)` 会**漏掉最后一个节点**；`strcmp(..., *name)` 对指针解引用错误 |
| **影响** | 名称查询永远找不到尾节点药品；`*name` 解引用可能崩溃（如果 `name` 是数组名其实等价，但语义错误） |
| **修复** | 改为 `while (cur != NULL)` 和 `strcmp(..., name)` |

### P2-4 `medicine.c`：`listAllMedicines()` 多处缺陷

| 项目 | 内容 |
|------|------|
| **位置** | `src/medicine.c`，约第 169~188 行 |
| **问题** | (a) 参数 `MedicineNode* head` 类型错误；(b) `while (cur->next != NULL)` 漏尾节点；(c) 输出无换行符；(d) 末尾 `cur->data.minStock;` 后 `cur=cur->next` 不在循环体内 |
| **影响** | 列表输出格式错乱、漏最后一条、循环提前结束 |
| **修复** | 见 `docs/07-药品模块_CRUD补充教程.md` 第 7 节修复后完整代码 |

### P2-5 `hospitalization.c`：`addHospitalization()` 参数冗余

| 项目 | 内容 |
|------|------|
| **位置** | `src/hospitalization.c`，函数签名 |
| **问题** | 接收 `recordNo[20]` 参数，但内部用 `generateUniqueId("HOS", id)` 重新生成并覆盖 |
| **影响** | 参数形同虚设，调用方传入的住院号被忽略 |
| **修复** | 去掉 `recordNo` 参数，或改为传出参数用于返回生成的单号 |

### P2-6 输入安全：大量 `scanf` 无返回值检查

| 项目 | 内容 |
|------|------|
| **位置** | 各 UI 菜单函数（`ui.c` / 教程代码） |
| **问题** | `scanf("%d", &choice)` 未检查返回值；若用户输入字母，变量未赋值导致无限循环 |
| **影响** | 界面卡死或异常跳转 |
| **修复** | 增加 `if (scanf(...) != 1)` 错误处理，并用 `while (getchar() != '\n');` 清空输入缓冲 |

## P3 — 完善性与工程化问题

### P3-1 `ui.h` 中 `showStatisticsMenu()` 和 `showQueryMenu()` 仅有声明无实现

| 项目 | 内容 |
|------|------|
| **位置** | `include/ui.h` / `docs/18-1-UI模块开发教程代码.md` |
| **问题** | 头文件声明了 `void showStatisticsMenu(void)` 和 `void showQueryMenu(void)`，但教程和源码均无实现 |
| **影响** | 主菜单 case 7/8 调用空函数（或链接错误） |
| **修复** | 补齐两个菜单函数，或暂时从主菜单移除对应选项 |

### P3-2 角色权限菜单未隔离

| 项目 | 内容 |
|------|------|
| **位置** | `src/login.h`、`src/main.c` / `ui.c` |
| **问题** | `UserRole` 定义了 患者/护士/医生/管理员 四种角色，但登录成功后 `main()` 未根据 `g_currentUserRole` 展示不同菜单 |
| **影响** | 所有角色看到相同的功能入口，权限控制形同虚设 |
| **修复** | 在 `showMainMenu()` 中根据 `g_currentUserRole` 过滤选项；或单独实现各角色的简化菜单 |

### P3-3 全局链表指针暴露方式不统一

| 项目 | 内容 |
|------|------|
| **位置** | 各模块 `.c` 文件 |
| **问题** | `patient.c` 用 `getPatientHead()` Getter；`bed.c/hospitalization.c` 直接 `extern Bed* g_bedHead`；`ui.h` 用 `extern Medicine* g_medHead` |
| **影响** | 链接时可能多重定义；风格混乱 |
| **修复** | 统一方案：要么全用 Getter/Setter（推荐），要么全用 `extern` 并在单一 `.c` 文件中定义 |

### P3-4 头文件缺少自给自足的标准库引用

| 项目 | 内容 |
|------|------|
| **位置** | `doctor.h`、`medicine.h`、`bed.h` 等 |
| **问题** | 使用 `int`、`char`、指针类型，但没有 `#include <stdio.h>` / `<stdlib.h>` / `<string.h>` |
| **影响** | 头文件不能独立编译，必须依赖调用方预先包含 |
| **修复** | 每个头文件开头添加必要的 `#include` |

### P3-5 缺少 VS2022 项目文件

| 项目 | 内容 |
|------|------|
| **位置** | 仓库根目录 |
| **问题** | 仅有 Makefile，无 `.sln` / `.vcxproj`，在 VS2022 中无法直接打开 |
| **影响** | VS2022 用户需手动创建项目并添加所有源文件 |
| **修复** | 补充 Visual Studio 项目文件，或添加 `CMakeLists.txt` 供 CMake 生成 |

### P3-6 `delDoctor()` 与 `delBed()` 参数风格不一致

| 项目 | 内容 |
|------|------|
| **位置** | `doctor.c` / `bed.c` |
| **问题** | `delDoctor(Doctor** h, Doctor** t, DoctorData d)` 传值拷贝；`delBed(Bed** h, Bed** t, Bed* b)` 传指针 |
| **影响** | 风格不统一；按值拷贝在数据量大时低效 |
| **修复** | 统一改为传指针（如 `delDoctor(..., Doctor* d)`），减少不必要的结构体拷贝 |

### P3-7 `registration.c` 整体缺失

| 项目 | 内容 |
|------|------|
| **位置** | `src/registration.c` |
| **问题** | 文件存在但函数未完全实现，UI 教程已跳过 |
| **影响** | 挂号系统不可用 |
| **修复** | 需补充完整的挂号 CRUD 及与 `doctor.c` 中 `canAcceptPatient()` / `incrementPatientCount()` 的联动 |

## 建议修复顺序

1. **先修 P0**：全部语法/类型错误，确保项目能通过编译
2. **再修 P1**：补齐药品 CRUD、住院预交金追加，让核心功能闭环
3. **然后 P2**：修复运行时会出问题的逻辑缺陷（如 `listAllMedicines`、输入安全）
4. **最后 P3**：完善菜单、权限、工程文件

> 如需批量修复后的完整 `.c`/`.h` 文件，可指定具体模块继续生成。
