# 医院综合信息管理系统 - 三人分工详细方案

> **项目**：吉林大学《程序设计基础课程设计》医院综合信息管理系统
> **团队**：3人协作，仅掌握C语言，处于开发阶段
> **组长**：承担最难部分（双向链表 + 挂号跨模块调用）

## 二、每人必须学的知识（学习顺序）

### 👑 组长（你）— 学习量最大，但你有基础最快

#### 必学文档（按顺序）：

**① `docs/04-数据结构.md`** — 双向链表（0.5天）

> 你已经会单向链表了，这个文档只需要看第2节"单向链表 vs 双向链表"和第4节"链表操作详解"里的双向部分。核心就是：每个节点多一个 `pre` 指针指向前面，删除节点时多一步 `p->pre->next = p->next`。1~2小时就能掌握。

**② `docs/05-病人模块.md`** — 照着写（1天）

> 定义结构体 → 写增删改查函数。逻辑和你 scoresystem 的 `addStudent/deleteStudent/modifyStudent` 完全一样，只是多了 `pre` 指针。

**③ `docs/06-医生模块.md`** — 照着写（1天）

> 和病人模块几乎一模一样，只是多了一个"每日接诊数量限制"的逻辑（`currentPatients < maxPatients` 就允许挂号，否则拒绝）。这个逻辑会在你的挂号模块里用到。

**④ `docs/09-挂号模块.md`** — 最复杂，但文档写得清楚（2天）

> ⚠️ 这是整个项目里逻辑最复杂的模块，因为挂号需要：
> - 检查病人是否存在（调用 `patient` 模块）
> - 检查医生今天是否还有名额（调用 `doctor` 模块的 `currentPatients`）
> - 挂号成功后让医生接诊数 +1（调用 `doctor` 模块）
>
> 这个模块涉及**跨模块调用**，是你们项目最难的部分，你作为组长必须啃下来。

#### 你的工作价值：

- 双向链表基础（给全组打样）
- 核心业务逻辑（挂号）
- 最复杂的跨模块调用

---

### 成员2 — 相对独立，不涉及模块间调用

#### 必学文档（按顺序）：

**① `docs/13-工具函数.md`** — 工具函数（0.5天）

> 项目里所有模块都会用到的通用函数，比如：
> - `generateUniqueId()` — 生成唯一ID（每个模块都要用）
> - `getCurrentTime()` — 获取当前时间
> - `safeStringCopy()` — 安全复制字符串
> - `isValidPhone()` / `isValidIdCard()` — 输入验证
>
> **这个文件非常重要**，建议成员2先写这个，其他所有模块都依赖它。

**② `docs/12-文件IO.md`** — 文件读写（1天）

> 逻辑和你 scoresystem 的 `loadFromFile/saveToFile` 几乎一样，只是文件格式从简单文本变成了带标记位的格式（每条记录前写 `1`，文件末尾写 `-1`）。文档里有完整代码示例。

**③ `docs/10-登录模块.md`** — 登录系统（1天）

> MD5 加密只需要会**调用** `md5Hash(password, hashed)` 这一行，不需要理解原理。剩下的就是用户链表的增删改查，和其他模块完全一样。

#### 成员2 的工作价值：

- 为全组提供工具函数基础设施
- 实现文件持久化（没有这个，项目数据不能保存）
- 登录系统

---

### 成员3 — GUI 部分较新，但文档齐全

#### 必学文档（按顺序）：

**① `docs/04-数据结构.md`** — 双向链表（0.5天）

> 同样只需要看双向链表部分，每个模块都要用到。

**② `docs/07-药品模块.md`** — 药品（1天）

> 药品模块的特点是多了"库存预警"和"购药记录"。逻辑不复杂：
> - 添加药品、删除药品、修改药品（和其他模块一样）
> - **库存预警**：检查 `stock <= minStock` 就打印警告
> - **购药**：把 `stock` 减去购买数量

**③ `docs/08-住院床位模块.md`** — 住院+床位（2天）

> 这是第二复杂的模块，因为：
> - **住院依赖床位**：入院时自动分配空闲床位（遍历链表找 `status == "空闲"` 的床位）
> - **出院依赖床位**：出院时释放床位（把状态改回"空闲"）
> - 这两个模块高度关联，建议一起写

**④ `docs/11-GUI界面.md`** — StellarX 图形界面（3~5天）⚠️

> 这是成员3最独特的工作，其他人都不用学：
> - 照着文档里的代码模板，创建 `Window`、`Button`、`TextBox`、`Table` 等组件
> - 把各模块的增删改查功能用按钮和表格展示出来
> - **建议**：先完成所有模块的命令行版本，最后再接 GUI。GUI 只是"外壳"，核心业务逻辑在各模块 `.c` 文件里已经写好了。

#### 成员3 的工作价值：

- 药品库存管理
- 住院与床位联动
- 图形界面（加分项，也是最能打动老师的部分）

## 三、实际开发顺序（建议）

### 第一阶段：基础设施（所有人并行）— 第1~3天

```
组长：读 docs/04（双向链表），开始写 patient.c/h
成员2：写 utils.c/h 和 file_io.c/h（其他人的模块都依赖这个）
成员3：读 docs/04，读 docs/07，开始写 medicine.c/h
```

### 第二阶段：各模块独立开发 — 第4~10天

```
组长：完成 patient.c/h → doctor.c/h → registration.c/h（含跨模块调用）
成员2：完成 file_io.c/h（关联所有人）→ login.c/h
成员3：完成 medicine.c/h → hospitalization.c/h → bed.c/h
```

### 第三阶段：主程序整合 + 编译调试 — 第11~14天

```
组长：写 main.c/main_gui.cpp，整合所有模块的调用
成员2：完善 file_io.c，处理各模块的全局变量暴露问题
成员3：开始写 GUI（有余力的话）
```

### 第四阶段：GUI + 测试 + 文档 — 第15~21天

```
全体：测试增删改查全流程
成员3：重点完成 GUI 界面
组长：准备答辩材料
```

## 四、GitHub 协作分工

你们三个人在三个分支上工作，最后合并：

```bash
# 每个人克隆后，创建自己的分支
git checkout -b feature/patient-doctor-reg      # 组长
git checkout -b feature/utils-login-fileio      # 成员2
git checkout -b feature/medicine-hospital-bed-gui # 成员3
```

| 分支名 | 谁 | 负责内容 |
|--------|---|---------|
| `feature/patient-doctor-reg` | 组长 | 病人+医生+挂号模块 |
| `feature/utils-login-fileio` | 成员2 | 工具函数+登录+文件IO |
| `feature/medicine-hospital-bed-gui` | 成员3 | 药品+住院+床位+GUI |

**每天开始前**：`git pull` 拉最新代码
**每天结束后**：`git push` 推送当天写的代码
**每周至少一次**：合并到 `main` 分支，提前解决冲突

## 五、组长额外要做的事

作为组长，除了写代码，你还需要：

1. **定接口规范** — 提前和成员2约定好全局变量的命名规则（比如 `g_patientHead`、`g_doctorHead`），避免合并时变量名冲突
2. **整合 `main.c`** — 所有模块写完后，你要负责写程序入口 `main.c`，把各模块串起来
3. **审核代码** — 定期看看成员们写的代码，确保风格一致
4. **把控进度** — 对照 `docs/小组复刻计划书.md` 里的开发计划表格，确保不落后

## 七、scoresystem 对医院项目的帮助（组长参考）

| scoresystem 里你会的 | 医院项目对应 |
|----------------------|-------------|
| `struct Student` | `struct Patient / Doctor / Medicine` 等（完全一样的写法）|
| `Node *createNode()` | 直接改字段名就是 `Patient *createPatient()` |
| `appendNode()` 尾插法 | 完全一样，加个 `pre` 指针而已 |
| `deleteStudent()` | `delPatient()` — 逻辑一样 |
| `modifyStudent()` | `modifyPatient()` — 逻辑一样 |
| `loadFromFile()` | `buildPatientChain()` — 格式略有不同 |
| `saveToFile()` | `rebuildPatientFile()` — 格式略有不同 |
| `printlist()` 遍历 | `listAllPatients()` — 换汤不换药 |

**最大的区别就两个**：
1. 单向链表 → 双向（多一个 `pre` 指针）
2. 文件格式加了标记位（`1`/`-1`）
