# 15-权限区分管理与日志系统

## 基于现有功能的权限区分管理及日志记录实现方案

本章节基于src目录中已经完成的功能，详细说明在医疗管理系统中实现4种身份（患者、护士、医生、管理员）权限区分管理的方案，并添加完整的日志记录功能，完全基于现有的结构体定义。

## 1. 概述

医疗信息系统的权限管理是保障系统安全性和数据隐私的重要组成部分。本系统采用基于角色的访问控制（RBAC）模型，通过定义不同角色及其权限来实现细粒度的访问控制，并通过日志系统记录所有关键操作。

## 2. 现有数据结构分析

### 2.1 用户结构体 (来自 login.h)
```c
typedef struct UserData {
    char username[50];           // 用户名
    char password[100];          // 密码（MD5加密）
    int role;                    // 角色（0=用户, 1=管理员）
    char lastLogin[30];          // 最后登录时间
} UserData;

typedef struct User {
    UserData data;
    struct User* next;
    struct User* pre;
} User;
```

### 2.2 挂号结构体 (来自 registration.h)
```c
typedef struct RegistrationData {
    char regNo[20];              // 挂号单号（如REG001）
    char patientCardNo[20];      // 患者卡号
    char patientName[50];        // 患者姓名
    char doctorEmpNo[20];        // 医生工号
    char doctorName[50];         // 医生姓名
    char dept[50];               // 科室
    char date[20];               // 挂号日期
    char status[20];             // 状态（待就诊/就诊中/已取消）
} RegistrationData;

typedef struct Registration {
    RegistrationData data;
    struct Registration* next;
    struct Registration* pre;
} Registration;
```



## 4. 角色映射

由于现有系统中role字段只区分普通用户和管理员(0=用户, 1=管理员)，我们需要在此基础上扩展角色概念：

```c
// 在新的权限管理中，我们基于用户名和预设的角色分配来确定具体角色
typedef enum {
    PATIENT_ROLE = 0,    // 患者（对应原系统中的普通用户）
    NURSE_ROLE = 1,      // 护士（扩展角色）
    DOCTOR_ROLE = 2,     // 医生（扩展角色）
    ADMIN_ROLE = 3       // 管理员（对应原系统中的管理员）
} ExtendedRole;
```

## 5. 权限验证函数实现

### 5.1 权限验证函数定义 (permission_control.h)
```c
#ifndef PERMISSION_CONTROL_H
#define PERMISSION_CONTROL_H

#include "login.h"
#include "registration.h"
#include "patient.h"
#include "doctor.h"

// 扩展角色定义
typedef enum {
    PATIENT_ROLE = 0,    // 患者
    NURSE_ROLE = 1,      // 护士
    DOCTOR_ROLE = 2,     // 医生
    ADMIN_ROLE = 3       // 管理员
} ExtendedRole;

// 权限验证函数声明
ExtendedRole getUserExtendedRole(const char* username);  // 获取用户的扩展角色
int checkPermission(int basicRole, ExtendedRole extendedRole, const char* operation);  // 检查权限
int canAccessPatientData(int basicRole, ExtendedRole extendedRole, const char* requestingUser, const char* targetPatient);  // 检查访问患者数据权限
int canManageRegistration(int basicRole, ExtendedRole extendedRole, const char* requestingUser, const char* regPatientCardNo);  // 检查管理挂号权限
int canUpdateMedicalRecord(int basicRole, ExtendedRole extendedRole);  // 检查更新病历权限
int canViewFinancialData(int basicRole, ExtendedRole extendedRole);  // 检查查看财务数据权限
int canManageUsers(int basicRole, ExtendedRole extendedRole);  // 检查管理用户权限
int canAccessSystemConfig(int basicRole, ExtendedRole extendedRole);  // 检查访问系统配置权限

// 角色检查函数
int isPatient(int basicRole, ExtendedRole extendedRole);
int isNurse(ExtendedRole extendedRole);
int isDoctor(ExtendedRole extendedRole);
int isAdmin(int basicRole);

#endif
```


## 8. 安全措施

### 8.1 最小权限原则
- 用户仅获得完成工作所需的最小权限集
- 功能权限严格按角色划分
- 数据访问范围限制在必要范围内

### 8.2 操作审计
- 关键操作日志记录
- 用户行为轨迹追踪
- 异常操作监控与报警
- 审计日志安全存储

### 8.3 数据保护
- 敏感信息加密存储
- 访问日志记录
- 会话超时管理

### 8.4 输入验证
- 参数合法性检查
- 数据格式验证


## 10. 实施建议

1. **严格遵循权限控制原则**，确保数据安全和隐私保护
2. **在关键代码处添加详细的权限检查注释**，便于维护
3. **建立权限变更审批流程**，防止权限滥用
4. **定期审查权限分配情况**，及时调整不合理权限
5. **进行权限安全测试**，确保权限控制有效
6. **定期清理日志文件**，避免占用过多磁盘空间
7. **监控日志文件大小**，实现日志轮转功能
