# 医疗管理系统权限管理设计

## 权限模型概述

### 用户角色定义
系统定义了三种核心用户角色，每种角色具有不同的权限和功能：

#### 1. 患者 (PATIENT)
- **主要功能**：
  - 预约挂号
  - 现场挂号
  - 查看个人挂号记录
  - 取消个人挂号
- **权限限制**：
  - 只能操作自己的挂号记录
  - 不能访问其他患者信息
  - 不能查看医生工作台

#### 2. 护士 (NURSE)
- **主要功能**：
  - 查看科室挂号列表
  - 协助叫号操作
  - 查看候诊队列
  - 挂号管理（辅助功能）
  - 患者引导和分流
- **权限限制**：
  - 通常只能取消待就诊状态的挂号
  - 不能修改医生的诊疗状态
  - 访问权限限定在负责的科室

#### 3. 医生 (DOCTOR)
- **主要功能**：
  - 查看个人今日挂号列表
  - 叫号操作
  - 查看候诊队列
  - 更新就诊状态（待就诊→就诊中→已完成）
  - 查看患者病历信息
- **权限限制**：
  - 只能管理自己科室的患者
  - 不能访问其他医生的患者信息

## 权限控制实现

### 1. 登录验证
- 用户名密码认证
- 角色信息加载
- 会话管理

### 2. 功能权限控制
在每个功能函数中实现权限检查：
```c
int cancel_registration(int reg_id, int user_id, UserType user_type) {
    Registration* current = g_registrations;
    while (current) {
        if (current->reg_id == reg_id) {
            // 检查权限：患者只能取消自己的挂号，医生和护士可以取消待就诊的挂号
            if ((user_type == PATIENT && current->patient_id == user_id) ||
                ((user_type == DOCTOR || user_type == NURSE) && current->status == 0)) {
                // 执行操作
            } else {
                return -1;  // 权限不足
            }
        }
        current = current->next;
    }
    return -1;  // 未找到挂号记录
}
```

### 3. 菜单动态显示
根据用户角色动态显示相应的功能菜单：
- 患者菜单：预约、查看记录、取消挂号等
- 医生菜单：查看挂号、叫号、更新状态等
- 护士菜单：查看列表、协助叫号、队列管理等

## 其他用户需求考虑

### 1. 管理员角色
虽然当前设计未显式包含管理员，但可以考虑扩展：
- 系统配置管理
- 用户账户管理
- 数据统计分析
- 系统监控维护

### 2. 超级用户需求
- 紧急情况下的权限提升
- 系统数据维护
- 用户权限调整

### 3. 科室主任/护士长
- 本科室全局视图
- 工作量统计
- 人员调度

## 安全措施

### 1. 最小权限原则
- 用户只能访问完成工作所必需的最小数据集
- 功能权限严格按照角色划分

### 2. 操作审计
- 记录关键操作日志
- 追踪权限使用情况
- 异常操作监控

### 3. 数据隔离
- 不同角色的数据访问域隔离
- 敏感信息保护

## 扩展性考虑

### 1. 角色权限配置化
- 将权限配置外部化
- 支持动态权限调整
- 便于系统维护

### 2. 细粒度权限
- 基于资源的操作权限
- 时间段权限控制
- 数据级别的访问控制

### 3. 角色继承
- 支持角色层次结构
- 便于权限管理
- 减少重复配置

## 实施建议

1. 严格遵循权限控制原则，确保数据安全
2. 在代码中加入详细的权限检查注释
3. 定期审查权限分配情况
4. 建立权限变更的审批流程
5. 提供权限管理的可视化界面
