## 2. 源代码组织原则

### 2.1 模块化设计原则

**单一职责原则：**
- 每个.c文件负责一个特定功能领域
- 避免功能混杂在一个文件中

**示例：**
```c
// patient.c - 仅负责患者相关操作
// doctor.c - 仅负责医生相关操作
// registration.c - 仅负责挂号相关操作
```

**开闭原则：**
- 对扩展开放，对修改封闭
- 通过接口实现功能扩展

### 2.2 文件命名规范

**源文件命名：**
- 使用小写字母和下划线
- 文件名与功能模块对应
- 保持一致性

**头文件命名：**
- 与对应源文件同名
- 使用.h扩展名
- 包含必要的保护宏

**示例：**
```c
// 正确的命名
patient.c
patient.h
user_management.c
user_management.h

// 错误的命名
PatientModule.c
patientMod.h
```

### 2.3 目录结构设计

**src/目录：**
- 存放所有.c和.cpp源文件
- GUI框架源码单独存放
- 按功能模块组织

**include/目录：**
- 存放所有.h头文件
- GUI框架头文件单独存放
- 与src/目录结构对应

**data/目录：**
- 存放运行时数据文件
- 备份文件单独存放
- 按数据类型组织

```
      │                   │
      └─────────┬─────────┘
                ▼
        data/patient.txt
        data/doctor.txt
```

### 3.2 依赖管理

**避免循环依赖：**
```c
// 错误：循环依赖
// patient.h 包含 doctor.h
// doctor.h 包含 patient.h

// 正确：使用前置声明
// patient.h
struct Doctor;  // 前置声明
typedef struct Patient {
    struct Doctor* assignedDoctor;  // 使用指针
} Patient;
```

**依赖方向：**
- UI层依赖业务逻辑层
- 业务逻辑层依赖数据访问层
- 数据访问层不依赖其他业务层

## 5. 构建系统组织

### 5.1 Makefile组织

```makefile
# 医院信息管理系统 - Makefile

CC = gcc
CFLAGS = -Wall -Wextra -std=c99 -g -Iinclude
SRCDIR = src
OBJDIR = obj
BINDIR = bin
DATADIR = data

# 源文件列表
SOURCES = $(wildcard $(SRCDIR)/*.c)
OBJECTS = $(SOURCES:$(SRCDIR)/%.c=$(OBJDIR)/%.o)

# 目标文件
TARGET = $(BINDIR)/hospital_system.exe

# 创建必要目录
DIRECTORIES = $(OBJDIR) $(BINDIR) $(DATADIR)

# 默认目标
all: directories $(TARGET)

# 创建目录
directories: $(DIRECTORIES)
$(DIRECTORIES):
	mkdir -p $@

# 链接目标
$(TARGET): $(OBJECTS)
	$(CC) $(OBJECTS) -o $@ -lm
	@echo "构建完成: $(TARGET)"

# 编译源文件
$(OBJDIR)/%.o: $(SRCDIR)/%.c
	$(CC) $(CFLAGS) -c $< -o $@
	@echo "编译: $< -> $@"

# 清理
clean:
	rm -rf $(OBJDIR)/*
	rm -f $(TARGET)
	@echo "清理完成"

# 重新构建
rebuild: clean all

# 运行
run: $(TARGET)
	./$(TARGET)

# 安装
install: $(TARGET)
	cp $(TARGET) /usr/local/bin/

# 测试
test: $(TARGET)
	@echo "运行测试..."
	# 添加测试命令

.PHONY: all clean rebuild run install test directories
```
